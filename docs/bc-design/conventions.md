## 1. Naming

### 1.1 Internal vs external events vs commands

| Kind | C# name | Avro schema? | Transport | Canonical home |
|---|---|---|---|---|
| Internal domain event | `{State}DomainEvent` (e.g., `ProductPriceChangedDomainEvent`) | **No** | In-process via `IDomainEventHandler<T>` | [eshop-master-design.md § 3.2](../eshop-master-design.md) |
| External summary event | `{BusinessMoment}Event` (e.g., `OrderShippedEvent`, `InvoiceIssuedEvent`) | **Yes** | Kafka via transactional outbox | [events-catalog.md § 2](events-catalog.md) |
| Saga-issued / cross-BC command | `{Verb}{Target}Command` (e.g., `ReserveStockCommand`, `AuthorizePaymentCommand`) | **Yes** | Kafka via outbox | [events-catalog.md § 2](events-catalog.md) |
| Application command (CQRS, in-process) | `{Verb}{Target}Command` | **No** | `Platform.CQRS` mediator | [use-cases.md](use-cases.md) |
| Application query (CQRS) | `Get{Target}Query`, `Search{Target}Query`, `List{Target}Query` | **No** | `Platform.CQRS` mediator | [use-cases.md](use-cases.md) |
| Domain event handler | `{InternalDomainEvent}{Role}DomainEventHandler` (e.g., `ProductPriceChangedProjectionDomainEventHandler`, `ProductPriceChangedOutboxPublisherDomainEventHandler`) — the "U-D" suffix rule | — | — | [architecture-tests.md § 1.3](architecture-tests.md) |

**All external events MUST end in `Event`.** No exceptions: the convention is also enforced at infrastructure bootstrap — `docker-compose.yaml`'s `schema-registry-init` service walks `platform/Platform.SchemaRegistry.Contracts/Avro/**` and refuses to start if a `.avsc` filename lacks either the `Event` or `Command` suffix (rather than silently warning).

### 1.2 Schema namespaces and file layout

Avro namespace and file path are derived from the event identity:

- **Namespace:** `{Domain}.{Aggregate}` — PascalCase, e.g. `Catalog.Products`, `Inventory.Reservations`, `Payments.Transactions`
- **File path:** `platform/Platform.SchemaRegistry.Contracts/Avro/{Domain}/{Aggregate}/{SchemaName}.avsc`
- **Schema name = Avro `name` field = generated C# class name** — they MUST agree

When renaming a schema, rename the `.avsc` file AND update its `"name"` field AND regenerate the `.cs` via `generate-avro.ps1`. The Avro Schema Registry treats `name` changes as a new subject — never an evolution — so renames are breaking changes governed by § 3 below.

### 1.3 Kafka topic names

- **Event topics:** `{bc}.{aggregate-plural}` or `{bc}.{purpose}` — lowercase, dot-then-kebab (e.g., `catalog.products`, `inventory.stock-events`, `basket.sessions`)
- **Command topics:** `{bc}.{aggregate}-commands` — explicit `-commands` suffix (e.g., `ordering.order-commands`, `payments.payment-commands`)
- **DLT topics:** `{topic}.{Service}.DLT` with `{Service}` matching the consumer's service name (e.g., `notifications.notify-commands.Notifications.DLT`) — per [kafka-dlt-strategy.md](kafka-dlt-strategy.md)

Canonical registries (per [ADR-0033](../adr/0033-kafka-topic-contract-doc-ssot.md)): per-**topic** physical topology (partitions / retention / class) → [kafka-topology.md](../kafka-topology.md); per-**event** contract (producer / consumers / group / correlation key / trigger / schema path) → [events-catalog.md § 2](events-catalog.md). The master design and individual BC docs MUST link to these rather than duplicate them.

## 3. Avro schema evolution

Canonical policy: [ADR-0007](../adr/0007-avro-compatibility-modes.md); the class → mode mapping lives in [kafka-topology.md](../kafka-topology.md). **Compatibility mode is *derived*** from topic class — event-log → `FORWARD_TRANSITIVE`, command → `FULL_TRANSITIVE`, global fallback `FORWARD_TRANSITIVE` — and machine-enforced by `schema-registry-init` via the `.avsc` filename suffix. Not tabulated per topic ([ADR-0033](../adr/0033-kafka-topic-contract-doc-ssot.md)).

Operational invariants:

- **Never hand-edit generated `.cs` files** next to a `.avsc` — they are regenerated by `platform/Platform.SchemaRegistry.Contracts/generate-avro.ps1 <path/to/schema.avsc>`. Commit the `.avsc` and the regenerated `.cs` together. Full procedure and its traps: [`.claude/avro.md`](../../.claude/avro.md).
- **Renaming an Avro `name` is breaking** — it creates a new schema subject. Treat as a new event for compatibility purposes; for production this would warrant a parallel-publish window. The repo is non-production (see [ADR-0009](../adr/0009-reference-solution-target-profile.md)) so renames are applied directly.
- **Subject registration is dynamic** — `schema-registry-init` walks `platform/Platform.SchemaRegistry.Contracts/Avro/**`, derives each subject as `{namespace}.{name}` (Record-Name Strategy), and sets compat by the `Event`/`Command` filename suffix. There is **no hand-maintained subject list** to keep in sync (see [ADR-0007 § Implementation Notes](../adr/0007-avro-compatibility-modes.md)).

## 4. Time and timezones

Canonical policy: [ADR-0015](../adr/0015-time-timezone-policy.md).

- Domain types use `DateTimeOffset` — never `DateTime`. Postgres column type is `timestamptz`.
- Avro timestamps use `{"type": "long", "logicalType": "timestamp-millis"}` — matches Kafka's native message-timestamp unit and the precision Kafka Connect / ksqlDB preserve without truncation.
- Domain code calls `TimeProvider.GetUtcNow()` — never `DateTimeOffset.UtcNow` or `DateTime.UtcNow`. Architecture tests enforce this.

## 5. Error discipline

Canonical taxonomy: [error-taxonomy.md](error-taxonomy.md) (per-BC tables + C# sketches).

| Situation | Mechanism |
|---|---|
| User-actionable error (validation, business rule, conflict) | Return `Result.Fail(<TypedError>)` — typed error inherits from a `*Error` base; `error-taxonomy.md` lists them per-BC |
| Bug-class violation (precondition the caller should have satisfied) | `throw new DataIntegrityException("Bc.ErrorCode", "human-readable")` or a specialised `*Exception` per BC |
| FSM transition guard | `if (!Status.CanTransitionTo(target)) { throw new DataIntegrityException(...); }` — bug-class, because saga / handler should have already filtered |

The result-vs-exception split above is mandatory: use the result pattern for expected errors and reserve exceptions for the bug path. Cross-cutting middleware (HTTP, Kafka inbox) maps each error class to its transport-level representation (404 / 409 / 503 / DLT).

## 6. Idempotency, outbox, inbox

- **Outbox** (`Platform.ReliableMessaging.Outbox.EFCore`) — the outbox row is written **in the same DbContext transaction** as the aggregate save. The outbox relay sidecar later publishes to Kafka with schema-registry validation.
- **Avro serialization is verified centrally, not per BC.** The saga (`SagaOrchestrators.IntegrationTests`) and BFF (`EShop.BFF.IntegrationTests`) suites exercise the real Confluent Avro serializer + Schema Registry round-trip via `KafkaTestProducer` against a `SchemaRegistryTestContainer`. Per-BC outbox tests swap in `FakeOutboxWriter` (empty `AvroPayload`) and assert **routing/shape** — topic, Kafka key, CLR event type — not the serialized bytes; each BC's domain→Avro mapping is covered by its `{Event}MapperTests`. A generated `ISpecificRecord` is its own schema, so there is no per-BC byte-fidelity gap to close.
- **Inbox** (`Platform.KafkaFlow.Inbox.EFCore`) — transport-level dedup keys on the `message.id` header. Redelivered messages short-circuit before the handler runs.
- **At-least-once everywhere.** Consumers MUST be idempotent. Transport dedup is the `message.id` inbox; durable per-channel dedup (where a handler has side effects beyond the inbox) is a domain ledger keyed by business identity — e.g. Notifications' `notification_deliveries` keyed `(NotificationId, Channel)` per [ADR-0031](../adr/0031-notify-user-command-and-notification-id.md).
- **Domain-event dispatch is owned by the persistence boundary, not application handlers.** EF-Core BCs (Catalog, Ordering, Invoicing, Payments) dispatch via `DispatchDomainEventsInterceptor` on the BC's `DbContext`; command handlers MUST NOT inject `IDomainEventDispatcher`. The two exceptions are Basket (Redis primary, dispatch in handler after `SaveAsync`) and Inventory (event-sourced, dispatch inside `EventStoreRepository.AppendAsync`). Canonical detail and per-BC wiring table: [ADR-0024](../adr/0024-domain-event-dispatch-in-persistence-interceptor.md).

## 7. Domain modelling

Per-BC: aggregate roots, value objects, SmartEnums, and domain events are documented in each BC's design doc under `docs/bc-design/{bc}.md` and its glossary `glossary-{bc}.md`. Cross-cutting modelling rules:

- **Aggregate root:** `sealed` class inheriting `Platform.SharedKernel.Base.AggregateRoot<TId>` (`TId` = `Guid` unless the BC has a specific reason — Basket uses `UserId` directly).
- **Value object:** `sealed record` inheriting `Platform.SharedKernel.Base.ValueObject`. Private ctor + `static Result<T> Create(...)` factory.
- **Factory methods on aggregates:** `static Result<TAgg> Create(...)` (or `static TAgg CreateFromXxx(...)` for ACL-input variants).
- **SmartEnum:** `Ardalis.SmartEnum<T>` with a readonly `_allowed` dictionary for guarded transitions — see `Ordering.Domain.Orders.OrderStatus` for the canonical eShop example.

### 7.1 Where a rule lives — functional core, imperative shell

This is the **domain model trilemma** (Khorikov, *Unit Testing Principles, Practices, and Patterns*). Three properties, and a design can hold at most two:

| Property | Means |
|---|---|
| **Completeness** | *All* domain logic sits in the domain model — nothing decided in a handler |
| **Purity** | The domain model touches no out-of-process dependency — no repository, no clock, no HTTP |
| **Performance** | No superfluous round-trips to those dependencies — don't load what a decision won't use |

The three ways out, and why this solution picks the first:

1. **Push I/O to the edges** — keeps purity + performance, **gives up completeness**. ← this repo
2. Inject dependencies into the domain model — keeps completeness + performance, gives up purity; the aggregate becomes untestable without fakes.
3. Let the domain decide what to load — keeps completeness + purity, gives up performance; you fetch eagerly for decisions that may not need it.

So the split is explicit:

- **A rule decidable from aggregate state alone stays in the domain.** No repository, no clock, no HTTP call reaches into it.
- **Application handlers do the out-of-process reading** — fetch what a decision needs, then pass it into the domain as arguments. A handler that hands an aggregate a repository has put the shell inside the core.
- **The lost completeness is the accepted price, not an oversight.** A rule that cannot decide without I/O legitimately lives in the handler. Do not "fix" it by pushing it into the aggregate — that trades away the purity this repo chose.

Layering and dependency rules are enforced by [architecture-tests.md](architecture-tests.md).

## 9. Manual code style (not *blocking*-enforced)

House **code-style** conventions `dotnet format` won't fail on: `var`-for-locals and the test AAA/naming items have no rule at all, and the casing rules that *do* exist in `.editorconfig` sit at `suggestion` severity (non-blocking). (Documentation style — XML/aggregate-docs, high-signal markdown — has its own SSOT: the `daca-documentation-reviewer` skill.)

- **`var` for locals** — always, whether or not the type is apparent.
- **Full, expressive names** — no abbreviations or single letters (`expiryDateUtc`, not `exp`; `subscriber`, not `s`).
- **Tests use AAA** — `// Arrange` / `// Act` / `// Assert` comment sections (skip one only when empty); group multiple assertions in a FluentAssertions `AssertionScope`, always the block form `using (new AssertionScope()) { … }` (never `using var _ = new AssertionScope();` — the braces delimit the scope's extent).
- **Test method names: `MethodName_Scenario_ExpectedResult`** — e.g. `FromCelsius_WhenValidInput_ReturnsCorrectTemperature`.

## 10. API response contracts

Canonical policy: [ADR-0037](../adr/0037-endpoint-owned-response-contracts.md).

- **Each endpoint owns its response type.** Response envelopes and their nested item types (the published wire contract) are **duplicated** per endpoint — never shared across sibling endpoints, even when identical today. Internal read-model projection helpers (EF `*Row` targets) are *not* covered — their sharing is [ADR-0021](../adr/0021-read-side-no-specifications.md)'s call, as is the **persisted** shape of a serialized projection column, which ADR-0021 forbids a wire type from ever being.
- **A value concept is shared only if it passes the knowledge test** — *would a change to one site always require the same change to the other?* `MoneyDto` passes (representation is an API-wide decision) and is shared within a BC, duplicated across BCs by design. `AddressDto` does not — billing and shipping addresses diverge — so it duplicates per endpoint like any item type. Being "a domain concept" is not sufficient; apply the test per type. **Sharing is licensed by name, never by location:** each BC's arch test carries an explicit allow-list of exempt types, so a type dropped into a `Common` folder gains nothing. [ADR-0037 § Implementation Notes](../adr/0037-endpoint-owned-response-contracts.md) has the per-type rulings and why a namespace anchor was rejected.
- **A standardized media type is shared when its standard states how consumers absorb a change to it** — RFC 9457 `ProblemDetails`, produced centrally by `Platform.Api`'s response sender. § 3.2 permits extension members *and* requires clients to ignore ones they do not recognize; that second half is what licenses sharing a shape that can still change. Neither structural genericity nor standardization alone qualifies.
- **A paging envelope is endpoint-owned**, not a shared wrapper — as is any other container an endpoint constructs, such as a batch envelope. A search page has reasons to change (facet counts) that a category listing does not. Every paginated envelope carries the same four members today; that is convergence, and an endpoint stays free to add what its own page needs. The shape, the rationale, and the revisit trigger: [ADR-0037 § Why a paging envelope is not a media type](../adr/0037-endpoint-owned-response-contracts.md).
- **Globally-unique simple names per OpenAPI document** — duplicated envelopes never share a simple name, however different their namespaces or their declaring assembly (a BC's document draws types from `.Api`, `.Application` and sometimes `.Domain`); NSwag's `ShortSchemaNames` (set in `SwaggerDependencyInjection`) otherwise collapses them to `Foo` / `Foo2`. Why that setting is kept, and why the domain is the document: [ADR-0037 § Risks](../adr/0037-endpoint-owned-response-contracts.md).
- **New response / item types are immutable, property-style records** — `public sealed record Foo { public required string Bar { get; init; } }`, not the mutable `class { get; set; }` shape. Positional records only for trivially flat types. `init` on an `IReadOnlyList<T>` member is shallow (prevents swapping the reference, not mutating the collection); acceptable for a serialize-immediately DTO.

## 11. Package versions

A `PackageReference` carries the package name only; the version is pinned in the nearest `Directory.Packages.props` above the project — `git ls-files '*Directory.Packages.props'` lists them.

- **A project resolves against exactly one of them.** MSBuild's search stops at the first file it finds walking up, and **no tier imports another**, so the tiers never merge. No repo-wide file sits above them.
- **A package two tiers both need is pinned in both** — what the per-tier layout produces, not an inconsistency to consolidate away. Repeated pins drift, so bumping a shared package means bumping every tier that carries it.

Introducing a *new* package — ask first: [_shared.md § 3](../implementation-prompts/_shared.md).
