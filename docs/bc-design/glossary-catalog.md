## Catalog Glossary

Terms authoritative for the **Catalog bounded context**. When a term has a different meaning in another BC, the distinction is noted under "In other BCs". Cross-reference with `docs/eshop-ubiquitous-language.md` (solution-level glossary) once that file is synthesized.

| Term | Definition |
|------|------------|
| Product | A sellable item definition in the catalog, composed of identity (`ProductId`), business key (`Sku`), descriptive content (name, description, images, dimensions, brand), a single category reference, a flat price (`Money`), and a lifecycle `Status`. A Product is the aggregate root that owns all write operations; it does not track stock on hand (that belongs to Inventory) and it is not the same thing as a basket line (Basket stores product snapshots, not live Product references). |
| SKU | Stock Keeping Unit. A human-readable business key for a Product. Unique across all products. 1–32 characters, alphanumeric + dashes, normalized to uppercase. Carried on every external event so downstream BCs can correlate without always holding the `ProductId`. |
| Category | A node in the Catalog taxonomy tree. Own aggregate root (not a child of Product). Carries `Name`, optional `ParentCategoryId`, and a materialized `CategoryPath`. Categories are referenced from Product by ID; the relationship is many-products-to-one-category. Categories with children or products cannot be deleted. |
| Category Path | A materialized path string (e.g., `/electronics/computers/laptops`) that encodes a Category's full ancestry as lowercase slug segments separated by `/`. Max depth 5 segments. Exposed on the `product_search_view` to enable fast prefix filtering without recursive CTEs or joins. |
| Category Breadcrumb | A denormalized, human-readable version of `CategoryPath` using category display names and the separator ` > ` (e.g., "Electronics > Computers > Laptops"). Computed once by the projection handler and stored on `product_search_view`; never computed at query time. |
| Price | A `Money` value object — strictly positive `Amount` plus an ISO 4217 `Currency` code — carried on the Product aggregate. Catalog v1 treats price as flat and single-currency per product per [ADR-0002](../adr/0002-pricing-in-catalog.md). Price changes go through `Product.UpdatePrice`, which raises `ProductPriceChangedDomainEvent` and publishes `ProductPriceChanged` externally. |
| Brand | A free-form `BrandName` value attached to a Product (non-empty, max 100 chars). In v1 brands are not their own aggregate; they are a descriptive string on Product. If brand management (brand pages, brand-level pricing) is added later, Brand may be extracted into its own aggregate or BC. |
| Product Status | A SmartEnum with values `Draft`, `Active`, `Discontinued`. Governs whether the Product may be sold: only `Active` products are sellable (consumed by Basket as a query-time validator). Transitions follow `ProductStatus.CanTransitionTo(target, adminReactivation)`: Draft→Active, Active→Discontinued, Discontinued→Active (admin only). |
| Discontinued | A terminal-looking but reactivatable `ProductStatus`. A discontinued Product cannot be added to new baskets and cannot be re-priced. It remains visible in historical orders and on detail pages. Discontinuation is irreversible without an explicit operator decision — hence `Reactivate(adminReactivation: true)`. |
| Reactivation | The act of moving a Product from `Discontinued` back to `Active`. Requires a dedicated flag (`adminReactivation: true`) on the `Product.Reactivate(...)` method. Raises `ProductReactivatedDomainEvent`. Reactivation is deliberately **not** published as an external event in v1 — consumers can infer the new state from a subsequent re-publish of `ProductCreatedEvent` if the use case materializes. |
| Read View | The denormalized `catalog.product_search_view` table that is the performance-optimized query target for Catalog reads. Built in-process by `ProductSearchViewProjectionHandler` from internal domain events, within the same transaction as the write-model save. Columns flatten Product + Category + Images to avoid joins at query time. |
| Draft | Initial `ProductStatus` for a newly created Product. A Draft product is **not** published externally as sellable; it is hidden from Basket (query-time validator rejects non-`Active` references). A Draft can be edited freely and, once complete, moved to `Active` via `Product.Activate()`. |
| Active | The sellable `ProductStatus`. An Active product may be added to baskets and purchased. Price changes, description edits, and re-imaging are allowed while Active. `Product.Activate()` is the only legal way in from `Draft`; the reactivation path from `Discontinued` requires the admin flag. |
| Dimensions | Optional value object (`Length`, `Width`, `Height`, `Unit`) attached to a Product. Present for physical goods, null for digital/service products. Units are whitelisted (`cm`, `mm`, `in`). Used downstream by shipping estimators (post-v1). |
| Image Reference | Value object (`Url`, `AltText`, `DisplayOrder`) representing one image associated with a Product. A Product carries a collection ordered by `DisplayOrder`; the entry with `DisplayOrder == 0` (if any) is the "primary" image. Stored JSON-serialized on the read view under `ImagesJson`. |

### In other BCs

- **Product**: Basket calls its own local, immutable copy of product data a *product snapshot* — not a Product. Ordering follows the same pattern (see [ADR-0005](../adr/0005-customer-data-in-ordering.md) for the analogous customer-data rationale). Inventory uses `ProductId` only and does not carry descriptive fields.
- **Category**: Not referenced outside Catalog except as an ID (`CategoryId`) and a path string (`CategoryPath`) on external events.
- **SKU**: Carried on most Catalog external events as a convenience; consumers should still treat `ProductId` as the authoritative identity.
